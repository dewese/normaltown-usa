# Normaltown USA — website

Static blog for [normaltownusa.com](https://www.normaltownusa.com). No platform fees:
posts are plain files, the site is generated by one Python script, and a free host
(Cloudflare Pages) serves it. Publishing a post = commit + push.

## How it works

- **Content lives in `Posts/<year>/<month>/<day>/`** — each post is a folder with:
  - `article.md` — the post (first `# ` line is the title). A `> ` blockquote right
    under the title is the **"In short"** answer box (shown at the top of the post and
    used as the schema abstract). A `## Questions I get about this` section whose
    `### ` headings are questions becomes visible FAQ content **and** FAQPage schema.
    A `## Sources` section (a list of `- [Label](https://...): what it backs up` items)
    is lifted out of the body and rendered as a **Sources** box under the post, listed in
    `llms-full.txt`, and emitted as `citation` in the BlogPosting schema. Cite the primary
    source (government page, the company's own guide, the study) for every number.
  - `publish.md` — supplies the URL slug, optional SEO **Title tag**, subtitle, meta
    description (≤160 chars), category (Money / Health / Bitcoin), image alt, and an
    optional `| **Updated** | YYYY-MM-DD |` row for when a post gets a real revision
  - one `.png` — the hero image
- **`build.py`** reads every post + the copy in `site/`, applies the brand, and writes
  the finished website to **`dist/`**. Zero dependencies (Python 3 standard library only).
- **Logo:** the SVG files in `brand/logo/` (full lockup, wordmark, icon) are copied to
  `dist/assets/` on every build. The header uses the full lockup; the icon is the favicon.
  To change the logo, replace the SVGs in `brand/logo/` and rebuild.
- **About page photo:** `site/about-family.jpg` (1400x1750) and `site/about-family-700.jpg`
  are the black-and-white family portrait, copied to `dist/about/` on build. To swap it,
  replace both files (4:5 crop) and rebuild; caption and alt text live in `build.py`.
  `site/author-headshot.png` (transparent black-and-white cutout) is the round avatar in the
  author box under every post; it is served at `/about/david-dewese.png`. `site/home-headshot.png`
  (850x850 round black-and-white portrait) sits to the right of the homepage intro and is the
  Person schema image, served at `/about/david-dewese-round.png`.
- **Resources page:** `site/resources.md` is the copy for `/resources/` (in the main nav) —
  the tools David actually pays for and uses, the free guides, and where paid digital
  products will go. Referral links are disclosed inline, next to each link.
- **Partner cards:** a block in any `site/*.md` shaped like

  ```
  :::partner CrowdHealth | Health sharing | crowdhealth-wordmark.svg | https://…/ref | Get 3 months at $99 | Affiliate link. Pays me $250 after 3 months.
  One-line lead sentence.

  Body paragraphs.

  ### The honest other half
  What it is not, and who it's wrong for.
  :::
  ```

  Fields are name, kind, logo file, link, button label, disclosure line. The card puts the
  kind *above* the logo (it's our note about them, not their ad), the logo is deliberately
  **not** a link, and the one affiliate link is the button at the bottom, after the honest
  limits, with the disclosure directly under it. A `### ` heading inside the block becomes
  the labelled honest-limits section. A missing logo file falls back to the name as text.
  `:::cta /contact/ | Label` renders the outline button used for our own offers; filled
  cyan is reserved for partner links so the two tiers stay visually ranked.
- **Partner logos:** in `brand/partners/`, copied to `dist/assets/partners/` (the
  `*-orig.*` originals and the script stay out of the build). Use the company's own
  wordmark SVG so the logo carries the name. Size each one in the CSS by its `.mark-<file
  stem>` class and match **cap height, not box height** — the two wordmarks have different
  ink-to-box ratios, so equal `height` leaves their letters visibly different sizes
  (CrowdHealth 18px vs River 26px reads as a match; 26px each does not). A logo drawn for
  a light background needs its dark text swapped for white first, which is a find-and-
  replace on the fill in the SVG; keep the untouched download as `*-orig.svg`.
  `brand/partners/make-mono.py` flattens a logo to white on `#0F0F0F` if a monochrome
  treatment is ever wanted instead; it's standard-library only, since there's no Pillow or
  ImageMagick on this machine.
- **Contact page:** `site/contact.md` is the copy; the form is built by `contact_form()` in
  `build.py` and posts to FormSubmit (free, no account) at `CONTACT_EMAIL`. Messages arrive
  with the sender as reply-to. Spam guard is a honeypot field; if spam grows, set `_captcha`
  to `true` in `contact_form()`.
- **`dist/` is committed** and served as-is, so the host needs no build step.
- **"Updated" dates are conservative.** A post shows an Updated date only when publish.md
  has an `Updated` row, or when a commit edited that article on its own. The commit that
  created the file and any commit touching more than `MASS_EDIT_FILES` (3) articles at
  once (a site-wide wording or template pass) are ignored, so a bulk edit never stamps
  every post with today's date.
- **Analytics:** Google Analytics 4 (`GA_ID` in `build.py`) loads on every page and only
  reports from the real hostname, so local previews are not counted. Search Console can
  verify ownership through this tag.
- **Footer email signup** appears on every page: beehiiv's inline embed (`NEWSLETTER_EMBED`
  in `build.py`, the loader script with the form id). beehiiv renders the field and button in
  an iframe; the "New posts by email" label and fine print around it are ours. The loader
  handles UTM/referrer attribution itself, so beehiiv's separate attribution.js is not used.
  Style the field and button in beehiiv (Subscribers → Subscribe forms → the form → Style):
  Slim layout, transparent background, no title/subtitle, Manrope, pill corners, cyan
  `#2DD4FF` button with `#0F0F0F` text. Setting `NEWSLETTER_EMBED = ""` falls back to a
  plain FormSubmit form that emails each signup to `CONTACT_EMAIL` and lands on `/subscribed/`
  (that page also works as beehiiv's post-signup redirect if you want one).
- **SEO / GEO is automatic.** Every page gets JSON-LD (WebSite, Organization, Person,
  BlogPosting + BreadcrumbList on posts, FAQPage where there are questions,
  CollectionPage on the `/money/`, `/health/`, `/bitcoin/` hubs), Open Graph + Twitter
  cards (default share image `site/og-default.png`), visible published/updated dates,
  a Sources box with `citation` schema where a post lists sources, reading time, related posts,
  prev/next links, an author box, `llms.txt` + `llms-full.txt`, an RSS feed with full
  text, a sitemap with `lastmod`, a `404.html`, and a Cloudflare `_headers` file.
- **Links to future-dated posts are safe.** The builder renders a link to a not-yet-live
  post as plain text, then turns it into a link on the day the post publishes.
- **Preview hostnames:** Cloudflare also serves the site at its default `*.workers.dev`
  address. Nothing links there; every page carries a canonical tag pointing at www and a
  one-line script that redirects any `*.workers.dev`, `*.pages.dev`, or bare-apex visit to
  `https://www.normaltownusa.com`. To hide it entirely: Cloudflare → Workers & Pages → the
  project → Settings → Domains & Routes → disable the workers.dev route.
- **Cloudflare gotcha:** the dashboard's *managed robots.txt* / *Content Signals* feature
  prepends rules that block GPTBot, ClaudeBot, Google-Extended, etc. Keep it OFF so
  `site/robots.txt` (which welcomes AI crawlers) is what gets served.

## Publish a new post

1. Add the post folder under `Posts/…` (article.md + publish.md + image.png).
2. Rebuild:
   ```
   python3 build.py
   ```
3. Preview locally (optional):
   ```
   python3 serve.py     # then open http://127.0.0.1:8787
   ```
4. Commit and push (then, optionally, `python3 indexnow.py` a couple of minutes later to
   ping Bing/DuckDuckGo/Yandex via IndexNow; the daily workflow does this automatically):
   ```
   git add -A && git commit -m "Add post: <title>" && git push
   ```
   Cloudflare Pages redeploys automatically in ~1 minute.

## Brand and theming (V2, 2026-09-21)

The site ships **two themes from one set of files**, following the reader's OS setting.

|  | Light (default) | Dark |
|---|---|---|
| canvas | `#FBF8F3` warm paper | `#141210` warm near-black |
| panel | `#F3EDE4` | `#1C1917` |
| ink | `#1B1917` | `#F7F3EC` |
| muted | `#5C5751` | `#A8A199` |
| accent | `#0E6F63` deep teal | `#4FC7B4` |
| warm | `#A54B24` clay | `#E8996A` |
| bitcoin | `#0E7490` | `#2DD4FF` |

The old identity (soft-black canvas, electric cyan) is **not gone**, it is the dark
theme. Cyan `#2DD4FF` scores 1.66:1 on warm paper, so it cannot be the light accent;
it survives as the bitcoin colour, scoped by `body.cat-bitcoin`, which `layout()`
sets from the post's category. Every pair in the table clears WCAG 2.1 AA on its own
background, which the accessibility statement promises.

Type: **Fraunces** (headlines) over **Manrope** (body and UI). A serif headline is what
makes the page read as a person writing rather than a product.

How one file serves both themes:

- **Logos** (`brand/logo/normaltown-logo.svg`, `brand/partners/*-wordmark.svg`) use
  `fill="currentColor"` for their text and `var(--brand-mark)` for their accent, and are
  **inlined** into the HTML by `inline_svg()`. Neither resolves through `<img src>`, which
  is why they are not `<img>` any more. `*-orig.svg` stays as the untouched download.
- **The favicon** carries its own `<style>` with a `prefers-color-scheme` query.
- **Post hero art** is the `.svg` next to each `article.md`, rewritten by
  `brand/theme-hero-svgs.py` to carry semantic classes (`f-bg`, `s-ink`, `f-ac`, …) plus
  an internal stylesheet. Browsers honour a `prefers-color-scheme` query inside an SVG
  even when it is loaded through `<img>`, so the art follows the theme with no second
  file. The script is idempotent and reuses `build.classify()` so bitcoin posts keep the
  cyan. Re-run it after adding a post:

  ```
  python3 brand/theme-hero-svgs.py && python3 build.py
  ```

  The `.png` beside it is still built and shipped, but only as the `og:image`, where a
  fixed dark rendering is fine and an SVG would be rejected by most social scrapers.

One idea per graphic, lots of negative space.

**Known gap:** `site/home-hero.jpg` and `site/about-family.jpg` are opaque JPEGs with a
dark background baked in, so on the light theme they read as black rectangles. Replacing
them with colour photographs is the single largest remaining warmth win and needs a
human with the original files.
